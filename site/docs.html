etchy docs

How to run etchy, read its output, and trust the result. etchy diffs two revisions of a board's fab output and reports — and measures — what changed.

Overview

What etchy is

etchy is a fast, open-source PCB visual & geometric diff tool, written in Rust. Point it at two directories of Gerber/Excellon files (an “old” and a “new” revision) and it computes, per layer, exactly what copper/mask/silk/paste was added and removed — as measured areas and region counts, with a desktop viewer (and a browser build of the same viewer) to see it.

It compares revisions of the same board using absolute coordinates — no auto-alignment — and fails loud rather than emit a wrong-but-quiet diff.

Install

Install

The etchy command-line tool ships as a single self-contained binary per OS (the etchy-cli-… archives), plus a distroless container. Grab the archive for your platform from Releases — the commands below name the current release, so swap the version if you take a later one.

# PowerShell — unpack the archive, then add the folder to your PATH
Invoke-WebRequest https://github.com/Cimos/etchy/releases/download/v0.1.1/etchy-cli-v0.1.1-windows-x86_64.zip -OutFile etchy.zip
Expand-Archive etchy.zip -DestinationPath .
.\etchy-cli-v0.1.1-windows-x86_64\etchy.exe --version
# static musl binary — no runtime to install
curl -LO https://github.com/Cimos/etchy/releases/download/v0.1.1/etchy-cli-v0.1.1-linux-x86_64.tar.gz
tar xzf etchy-cli-v0.1.1-linux-x86_64.tar.gz
sudo mv etchy-cli-v0.1.1-linux-x86_64/etchy /usr/local/bin/
# Apple Silicon — use …-macos-x86_64.tar.gz on Intel
curl -LO https://github.com/Cimos/etchy/releases/download/v0.1.1/etchy-cli-v0.1.1-macos-aarch64.tar.gz
tar xzf etchy-cli-v0.1.1-macos-aarch64.tar.gz
sudo mv etchy-cli-v0.1.1-macos-aarch64/etchy /usr/local/bin/
# from a clone — etchy is not on crates.io yet
git clone https://github.com/Cimos/etchy && cd etchy
cargo install --path crates/etchy-cli --features pdf
# distroless, no shell or libc inside
docker pull ghcr.io/cimos/etchy:v0.1.1
docker run --rm -v "$PWD:/work" ghcr.io/cimos/etchy:v0.1.1 --format summary -- /work/old /work/new

Check what you downloaded. Every release carries a SHA256SUMS file: download it next to the archive and run sha256sum -c SHA256SUMS --ignore-missing (shasum -a 256 -c on macOS).

The desktop viewer has its own installers on the Releases page: etchy-viewer-v0.1.1-windows-x86_64.msi, etchy-viewer-v0.1.1-macos-aarch64.dmg (Apple Silicon), etchy-viewer-v0.1.1-linux-x86_64.AppImage, and etchy-viewer-v0.1.1-linux-x86_64.deb. The MSI and DEB add the etchy CLI to PATH; Homebrew links it on macOS with brew install --cask cimos/etchy/etchy. The AppImage and a DMG opened directly do not put the CLI on PATH. The installers are not code-signed yet: Windows shows a SmartScreen prompt (More info, then Run anyway) and macOS asks you to allow the app once in System Settings, Privacy & Security. A browser build exists, but no hosted viewer is offered yet.

CLI usage

Run a diff

Point etchy at two directories of fab output. Layers are paired by kind, such as top copper or inner copper 1, so filenames may differ between revisions. When several files have the same kind, exact filename matches come first; remaining files pair in stack order only when their board extents plausibly overlap.

etchy <old> <new>                  # human-readable per-layer summary
etchy <old> <new> --format json    # machine-readable report on stdout

The summary lists each layer with changed area (mm²) and region counts. This is the real output on the two board revisions bundled in the repo:

Every flag

FlagWhat it does
<OLD> <NEW>The two revisions. Either two directories of Gerber / Excellon / centroid files, two .pdf files, or two git refs.
[SUBDIR]With git refs, the subdirectory in the repo where the fab files live (default: the repo root). Its presence implies --git.
--gitRead the committed files at each ref instead of the working tree — no checkout. Git mode is always explicit, so a mistyped directory stays a loud “not a directory” error instead of being read as a ref.
--format <FORMAT>summary (default) for the terminal, json for the versioned report, md for GitHub Markdown — a CI step summary or a PR comment.
--jsonDeprecated alias for --format json. Still works.
--svg <DIR>Write one SVG overlay per changed layer into this directory (00-top-copper.svg, 01-inner-copper1.svg, …). Created if missing.
--html <FILE>Write a single self-contained HTML report: totals, warnings, and every changed layer's overlay inlined. No external assets, so it travels as one file.
--fail-on-area <MM2>CI gate: exit 1 only when the changed area on the gated layers exceeds this many mm². With neither threshold set, any change on the gated layers fails.
--fail-on-regions <N>CI gate on the changed region count instead. Set both and either one being exceeded fails.
--gate-layers <SPEC>Which layers the gate looks at: all (default), or a comma list of copper, mask, silk, paste, drill, outline, documentation, placement, other. An unknown name is a loud error, never a silently disarmed gate.
--dpi <DPI>PDF inputs only: rasterization resolution, default 150. Higher is crisper but costs memory and time (per-page pixel area is capped).
--out <DIR>PDF inputs only: write one overlay PNG per diffed page (page-<n>.png) into this directory.
--min-region-px <N>PDF inputs only: keep changed regions under N connected pixels out of the overlay as likely anti-aliasing noise. Default 1, which hides nothing. Anything hidden is still counted and still reported — the floor can never produce a silent “no differences”.

Reports and exports

One run can write every output at once — they all come from the same diff computation, so the picture and the numbers can't disagree:

etchy old/ new/ --html diff.html --svg overlays/ --format json > diff.json

Diff two commits, no checkout

Give etchy two git refs and it reads the committed fab files straight out of the object store. A third argument scopes it to the subdirectory the Gerbers live in:

etchy v1.0 HEAD fab/          # <refA> <refB> [subdir]
etchy --git v1.0 HEAD          # whole repo; prints a scoping note

Schematic PDFs

Hand etchy two .pdf files instead of two directories and it does a page-by-page pixel diff, reporting added / removed / changed pixels and a changed-region count per page. Pages pair by content, not index, so inserting one sheet shows up as a single extra row rather than making every later page look rewritten.

$ etchy old.pdf new.pdf --out overlays/
etchy: wrote overlays/page-1.png
page    old  new present     added_px removed_px changed_px  changed%  regions
1         1    1 both        230          0         66    0.014%        3

1 page(s) diffed at 150 DPI; 1 changed
result: differences found

The PDF path lives behind the pdf cargo feature so its rasterizer stays out of a plain build — but the release binaries and the container are built with it on, so a downloaded etchy already has it. From source, add --features pdf. It is pure Rust: no PDFium, no C++ toolchain.

Exit codes — designed for CI. These three are the whole contract:

CodeMeaning
0Nothing to block on — either the two revisions are identical, or a gate is configured and the change came in under it
1Differences found — the revisions differ (the normal “what changed” result)
2Error — a comparison couldn't be made: the inputs aren't the same board (extents mismatch — etchy compares revisions of one board, not two different boards), a layer failed to parse, or files are missing
How the diff works

One computation, real geometry

  • Same-board only. etchy uses each file's absolute coordinates and does not auto-align. If the two revisions' extents differ beyond a small tolerance, it errors (“not the same board”) instead of producing a misleading diff.
  • Layer pairing. Layers are matched by filename and classified by kind (top/inner/bottom copper, mask, silk, paste, drill, outline).
  • Polygon boolean. Each layer is turned into polygons; the diff is a per-layer boolean: added = new − old, removed = old − new.
  • Magnitudes. From that one computation it reports changed area (mm²) and the number of regions added/removed per layer — the numbers you can threshold on in CI.
  • Dense boards. Layers are diffed in parallel, and each layer carries a hard ceiling on how much geometry it will take in, so a malformed or hostile file fails with an error instead of eating the machine.
JSON output

Machine-readable report

--format json emits a versioned report to stdout — totals, a per-layer array, any warnings, and the CI gate's verdict. schema_version is the integration contract: it only changes when the shape does.

CI usage

Gate a pull request

The exit code alone already gates a build — any change is exit 1, so the step fails:

- name: PCB diff
  run: etchy old/ new/        # exit 1 → step fails on any change

That is usually too blunt: a moved silkscreen label shouldn't block a board review. Gate on the magnitude and location of the change instead. Below, only copper counts, and only if more than 0.5 mm² of it moved:

- name: PCB diff
  run: etchy old/ new/ --gate-layers copper --fail-on-area 0.5

The gate names its verdict on stderr — etchy: gate FAIL — copper: changed 552.6209 mm², 1661 regions — and repeats it in the JSON, so why a build passed or failed is on the record. When a gate is configured and the change comes in under it, etchy exits 0 even though it found differences. That is the point of the gate.

Or add the Action. The five-line Action block below needs the trigger and permissions from the full pull-request recipe. It posts a layer-by-layer table as a sticky comment for that input pair (edited in place on each push, not re-posted):

- uses: Cimos/etchy@v0.1.1
  with:
    old: fab/rev-a
    new: fab/rev-b
    comment: true

The job needs pull-requests: write; etchy supplies its own token. Set fail-on-diff: false to report without failing the step, and read outputs.changed to branch on the result. The diff itself uses no hosted service. Posting a PR comment uses the GitHub API, so comment: true needs network access and does not work on a fully air-gapped runner. The Action compiles etchy on the runner, so budget a build the first time.

Feeding a CI step summary or another tool by hand instead? --format md writes the same table as GitHub Markdown, and --format json gives the numbers.

The viewer

See the diff

etchy-gui <old> <new> opens the same diff on screen. It is a separate binary from the CLI, built from a clone (cargo build --release -p etchy-gui), and the identical code also compiles to WebAssembly and runs in a browser — same layout, same behaviour, no install.

Modes

The top bar carries the board labels and a mode segment:

  • Overlay — one board with the diff drawn on it: added green, removed red, unchanged copper faint behind them.
  • Old / New — one revision at a time, no diff colouring.
  • Split — the two whole boards side by side through one shared camera, so pan and zoom stay locked together.
  • Swipe — a draggable curtain over a single board: old to the left of the divider, new to the right. The divider travels edge to edge and dragging it never pans the board.

Panels

A slim activity rail (flip it to either side in Settings) opens docked panels:

  • Layers — rows grouped by family (copper, soldermask, silkscreen, paste, drill, mechanical), changed ones first, each with a colour swatch and its changed share as a percentage; hover for the mm² split. Eyes are the only visibility control — selecting a row highlights it without hiding anything and without moving the camera. A Focus slider dims every visible layer you haven't selected, from “all equal” up to “selected layer only”, so you can bury a busy board without hiding it.
  • Measure — the ruler between the panel tabs is a plain tool toggle, not a panel (Ctrl+M does the same). Two clicks make a measurement; it stays drawn on the board with the distance, ΔX, ΔY and angle until you clear it. Units are mm / mil / inch.
  • Export — export the current layer or every changed layer, with the exact file list shown before it writes: index-prefixed SVGs plus areas.csv, the same code path the CLI uses. In PDF mode it exports the changed pages' overlay PNGs instead. Native writes an etchy-export/ folder next to the input and reports the absolute path; the browser build downloads a multi-file set as one zip.
  • Settings — a gear at the bottom of the rail, not a floating window: theme and rail side, base-copper opacity, the minimum-area noise filter, PDF resolution, grid spacing and colours, measure units and snapping, per-tool input presets (Altium or KiCad mouse and key conventions), per-layer colours, and a hotkey editor where every action can be rebound.

Getting boards in, and around them

Open old / Open new take a folder, a .zip, or a drag-and-drop. The wheel zooms at the cursor, left-drag pans in every preset, and F fits the whole board — the only thing that ever reframes the camera. A grid-snapped crosshair reads out live coordinates.

Schematic PDFs open here too: pass two PDFs and you get the page list with the same modes and per-page overlays. The rasterization resolution is a setting (150 / 200 / 300 DPI), and changing it re-renders the loaded pair.

Status chips sit bottom-left and only appear when they have something to say — the coordinate readout, how many regions the noise filter is hiding and below what size, and a note when only one of several layers is on screen. That stack is the trust rule made visible: nothing the viewer suppresses goes unaccounted for.

Trust & limitations

What it will and won't do

  • Fail loud, never wrong-but-quiet. Mismatched boards error rather than diff.
  • Same-board revisions only. No registration / auto-alignment — by design.
  • Inputs: Gerber RS-274X/X2, Excellon drill, pick-and-place centroid files (moved, rotated, added and removed parts diff as placement geometry — not as a BOM), and schematic PDFs page by page.
  • Nothing is hidden silently. A real change too small to draw to scale becomes a fixed-size marker dot rather than disappearing, and anything the noise filter suppresses is counted and shown on screen.
  • Non-goals: net/connectivity diff, BOM/component diff, DRC, and Altium / IPC-2581 / ODB++ ingestion. etchy diffs fab output — it isn't an ECAD review tool.
  • Next parser milestone: native KiCad .kicad_pcb input is planned for 0.2.0, so KiCad users can skip the Gerber export. KiCad schematic diff stays out — that's connectivity, a different tool.
