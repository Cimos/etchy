etchy docs

How to run etchy, read its output, and trust the result. etchy diffs two revisions of a board's fab output and reports — and measures — what changed.

Overview

What etchy is

etchy is a fast, open-source PCB visual & geometric diff tool, written in Rust. Point it at two directories of Gerber/Excellon files (an “old” and a “new” revision) and it computes, per layer, exactly what copper/mask/silk/paste was added and removed — as measured areas and region counts, with a native viewer to see it.

It compares revisions of the same board using absolute coordinates — no auto-alignment — and fails loud rather than emit a wrong-but-quiet diff.

Install

Install at first release

etchy ships as a single self-contained binary per OS, a Cargo crate, and a distroless container — pick your platform. (Distribution lands with the first release; the commands below are the planned form.)

Linux

# static musl binary — no runtime to install
curl -L https://github.com/Cimos/etchy/releases/latest/download/etchy-x86_64-unknown-linux-musl -o etchy
chmod +x etchy && sudo mv etchy /usr/local/bin/

macOS

# Apple Silicon (use x86_64-apple-darwin on Intel)
curl -L https://github.com/Cimos/etchy/releases/latest/download/etchy-aarch64-apple-darwin -o etchy
chmod +x etchy && sudo mv etchy /usr/local/bin/

Windows

# PowerShell — download etchy.exe, then add it to your PATH
Invoke-WebRequest https://github.com/Cimos/etchy/releases/latest/download/etchy-x86_64-pc-windows-msvc.exe -OutFile etchy.exe

Any OS — Cargo

cargo install etchy

Container

docker run --rm -v "$PWD:/work" ghcr.io/cimos/etchy /work/old /work/new

Build from source today: git clone https://github.com/Cimos/etchy && cd etchy && cargo build --release → target/release/etchy.

CLI usage

Run a diff

Point etchy at two directories of fab output. Layers are paired by filename, so both revisions must use the same Gerber filenames.

etchy <old> <new>          # human-readable per-layer summary
etchy <old> <new> --json   # machine-readable report on stdout

The summary lists each layer with changed area (mm²) and region counts:

$ etchy revA/ revB/
layer            status      added_mm2  removed_mm2  +regions  -regions
top-copper       changed      19.60342      0.00000       100         0
inner-copper1    changed       0.00000     19.60342         0       100
…
2 of 22 layer(s) changed; total +19.60 / -19.60 mm² (100+/100-)
result: differences found

Exit codes — designed for CI:

CodeMeaning
0No differences
1Differences found
2Error (e.g. boards aren't the same revision)
How the diff works

One computation, real geometry

  • Same-board only. etchy uses each file's absolute coordinates and does not auto-align. If the two revisions' extents differ beyond a small tolerance, it errors (“not the same board”) instead of producing a misleading diff.
  • Layer pairing. Layers are matched by filename and classified by kind (top/inner/bottom copper, mask, silk, paste, drill, outline).
  • Polygon boolean. Each layer is turned into polygons; the diff is a per-layer boolean: added = new − old, removed = old − new.
  • Magnitudes. From that one computation it reports changed area (mm²) and the number of regions added/removed per layer — the numbers you can threshold on in CI.
JSON output

Machine-readable report

--json emits a versioned report to stdout — totals plus a per-layer array:

{
  "schema_version": 1,
  "tool_version": "0.1.0",
  "any_changes": true,
  "totals": {
    "added_area_mm2": 19.60, "removed_area_mm2": 19.60,
    "added_regions": 100, "removed_regions": 100,
    "layers_changed": 2, "layers_total": 22
  },
  "layers": [
    {
      "kind": "top-copper", "inner_index": null,
      "label_old": "F_Cu.gbr", "label_new": "F_Cu.gbr",
      "status": "changed",
      "added_area_mm2": 19.60, "removed_area_mm2": 0.0,
      "added_area_nm2": "19603417231600", "removed_area_nm2": "0",
      "added_regions": 100, "removed_regions": 0
    }
  ]
}

Areas are given both as mm² (float) and exact nm² (integer string, for lossless thresholds). status is changed or unchanged.

CI usage

Gate a pull request roadmap

Today, the exit code already gates a build (1 = changes). Per-layer thresholds and inline PR comments are on the roadmap.

# fail the job when the board changed
- name: PCB diff
  run: etchy old/ new/        # exit 1 → step fails on any change

# coming: thresholds + PR comments
- run: etchy old/ new/ --fail-on copper-area=5mm2
The viewer

See the diff

The native desktop viewer (egui) opens the diff visually: a changed-layers-first list, with overlay (added green / removed red), before (old), and after (new) modes, plus pan / zoom / fit.

Trust & limitations

What it will and won't do

  • Fail loud, never wrong-but-quiet. Mismatched boards error rather than diff.
  • Same-board revisions only. No registration / auto-alignment — by design.
  • Inputs: Gerber RS-274X/X2, Excellon drill. Schematic-PDF page diff is planned.
  • Non-goals: native CAD ingestion (KiCad/Altium/IPC-2581/ODB++), net/connectivity diff, BOM/component diff, DRC. etchy diffs fab output — it isn't an ECAD review tool.
